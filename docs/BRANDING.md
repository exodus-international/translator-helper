# Branding assets

Where the identity lives, and how to redo any of it.

## The mark

`src/app/icon.svg` is the source of truth and the only thing to edit. Two
overlapping cards, source over target, with an omega on the orange front card.

Every raster icon is generated from it:

```sh
./scripts/generate-icons.sh
```

Nothing in that script upscales a PNG. Each size is rasterized from vector, so
a 512 icon is exactly as sharp as a 16 one. Rendering once and enlarging is
what produces blur, and is the mistake worth not making.

Requires `brew install librsvg imagemagick`.

## Colours

```
theme:      #FE5A25   the orange of the front card
background: #FFFFFF   the icons are flattened onto white, so the splash matches
```

`theme` tints mobile browser chrome. `background` is the splash colour behind
the icon while an installed app boots.

## Generated files

| File | Size | Notes |
| --- | --- | --- |
| `src/app/favicon.ico` | 16, 32, 48 | Tab icon |
| `src/app/apple-icon.png` | 180 | Flattened onto white — iOS paints transparency black. iOS rounds the corners itself, so no radius is baked in |
| `public/icon-192.png` | 192 | Manifest |
| `public/icon-512.png` | 512 | Manifest |
| `public/icon-maskable-512.png` | 512 | See below |
| `src/app/opengraph-image.jpg` | 1200 × 630 | Link preview card, not generated by the script |

### The maskable icon is smaller than "80%" suggests

Android crops this to whatever shape the launcher uses. Only a circle of 80%
diameter is guaranteed visible — and a *square* fits inside that circle only up
to `512 × 0.8 ÷ √2 ≈ 289px`, not 410. The script renders the mark at 288 and
centres it. Everything outside is bleed the launcher may cut away.

### The mark is soft at 16px

The mark carries two cards, an omega and the target-language strokes. At 16 px
that is more detail than the pixels can hold, and it reads as a coloured smudge
rather than a shape. 32 px and up are clean.

This is the accepted cost of every icon being the same mark. If the tab icon
ever matters more than that consistency, the fix is a simplified 16px slice —
the omega alone on an orange square, no back card — packed into `favicon.ico`
beside the full mark at 32 and 48. An `.ico` holds one image per size, so this
costs nothing anywhere else.

After any change to the mark, look at the magnified 16px slice the script
writes out. It is the size that will show a problem first.

## The preview card

`src/app/opengraph-image.jpg`: the supplied artwork cropped to 1200 × 630, with
a bottom-up dark scrim and the wordmark over it. Made by hand, not by the
script.

To recompose from new artwork:

1. Crop to exactly 1200 × 630 (`-resize 1200x630^ -gravity center -extent 1200x630`).
2. Lay a bottom-up dark gradient over the lower half so text stays readable
   whatever the artwork does there.
3. Title around 76px, tagline around 34px, in a serif.
4. Export JPEG at quality ~86. The current file is about 250 kB; the same image
   as PNG is 1.4 MB, which unfurlers are slow to fetch.

Slack renders the card around 360 px wide. Anything below roughly 40 px in the
1200 px source is unreadable there — that is why the type is as large as it is.

## One deployment requirement

`metadataBase` decides the origin `og:image` resolves against. Set **`APP_URL`**
to the public origin in each environment.

It must be `APP_URL`, not `NEXT_PUBLIC_APP_URL`. `NEXT_PUBLIC_*` values are
inlined when the image is built, so a value supplied only to the running
container never reaches the code. `APP_URL` is read on the server at runtime and
can be changed without a rebuild.

Verified against a production build: with `APP_URL` set, `og:image` renders as
`https://<origin>/opengraph-image.jpg`. Unset, it falls back to
`http://localhost:3000` and every unfurl outside dev breaks silently.

In `next dev` the tag always shows the dev origin regardless. That is dev
substituting the request host, not a misconfiguration — do not chase it.

## Still open

Per-document preview cards — a document link unfurling with its title, language
and status — are specified in the favicon + OG PRD. They need a crawler
exemption in `src/proxy.ts`, because every route currently redirects an
unauthenticated request to `/login`, which is exactly what a link-preview
crawler is. Until then every link shows the one card.
